# Snip 0.1.1 preview

Native macOS rolling capture. Press a shortcut to save the recent screen and sound as a `.mov` clip.

![How Snip turns ongoing capture into a saved clip](https://github.com/Duncanyu/clipper/releases/download/v0.1.1-preview/how-it-works.png)

## Download and install

Download **Snip-v0.1.1-preview-macos-arm64.zip** below. It requires Apple Silicon and macOS 15 or later. A SHA-256 checksum file is included.

1. Unzip and move **Snip.app** to **Applications**.
2. Open it. This preview is ad hoc signed and **not notarized**. If macOS blocks it, use **System Settings → Privacy & Security → Open Anyway** after the first attempt. See [Apple's guidance](https://support.apple.com/en-us/102445).
3. Grant **Screen & System Audio Recording** when asked. Quit and reopen Snip if you change this permission.
4. Choose **Settings** from the menu bar icon. Default shortcuts: **⌘⇧9** saves a clip; **⌘⌥P** pauses or resumes. Both can be changed.

## What changed

- Reduced overhead from high FPS selections on lower refresh displays. On a 60 Hz display, selecting 120 FPS requests at most 60 FPS.
- Expired audio packets now leave the rolling buffer without copying the full packet array on every audio callback.
- The README and benchmark report now show the capture flow, charts, raw samples, and a repeatable moving scene test.

The release retains full physical Retina capture, hardware HEVC encoding, system audio, app specific video and audio rules, recorded video color controls, custom output resolution, and a configurable buffer cap.

## Measured on one M4 Mac

![Snip CPU comparisons and full Retina clip metadata](https://github.com/Duncanyu/clipper/releases/download/v0.1.1-preview/performance.png)

At 2940 × 1912 Retina resolution with system audio and a 16 Mbps target, a 30-second moving scene measured **5.3% median CPU before** and **4.1% after** the audio buffer change. The corresponding clips remained 2940 × 1912 HEVC Main with AAC 48 kHz audio; median and 95th percentile frame gaps were 16.67 ms in both. The optimized clip lasted 30.479 seconds, averaged 57.38 decoded FPS, and measured 15.86 Mbps whole-file bitrate. CPU percentages are per logical CPU (100% is one core). These are single observations, not a gameplay benchmark or a guaranteed speedup.

See the [full method and limits](https://github.com/Duncanyu/clipper/blob/main/benchmarks/2026-10-13-m4.md), [raw samples](https://github.com/Duncanyu/clipper/tree/main/benchmarks/raw), and [README](https://github.com/Duncanyu/clipper#readme).
